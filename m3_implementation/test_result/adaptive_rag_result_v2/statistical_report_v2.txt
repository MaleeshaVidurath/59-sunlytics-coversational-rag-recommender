 E8  BASELINE COMPARISON  (does the trigger beat the alternatives?)
------------------------------------------------------------------------
  The two gaps claimed in the literature review are tested directly.

  [E8a] Latency vs retrieval-policy baselines
    Policy                                      Total (s)   vs ours
    B1 non-adaptive, always FULL (COMPASS/RA-Rec)     1349.3  +248.8 s
    B2 binary gate, 2-way (RAGate)                 1206.9  +106.4 s
    OURS 3-way NO/PARTIAL/FULL                     1100.5         -

    GAP 1  adaptive vs always-retrieve : 18.4% faster
    GAP 2  3-way vs binary gate        : 8.8% faster
           = the measured value of the PARTIAL tier alone: 106.4 s
           = 925 ms saved per PARTIAL turn (n=115)

  [E8b] Routing correctness vs decision-policy baselines
    Router                                       Accuracy
    Random (stratified, matches our marginals)      37.9%
    Majority class (always FULL)                    44.7%
    Intent label only (no CSE)                      95.0%
    OURS DistilBERT + CSE                           95.7%

    -> A random router matches our latency profile but routes correctly
       only 37.9% of the time. Latency alone therefore proves
       nothing; routing accuracy is what establishes the trigger works.

    -> CAVEAT: the intent-only row is a CEILING, scored on the logged
       label so it inherits none of the classifier's own errors, while
       our row is the live end-to-end system. The overall gap
       (+0.7 pp) therefore UNDERSTATES the CSE.
    -> The structural limit shows on FEEDBACK turns (n=27):
         intent-only 48.1%   vs   ours 96.3%
       Without the CSE, all 14 negative-feedback turns route to NO:
       the user says "I don't like them" and gets no new items at all.
       That is a functional failure, not a small accuracy delta.
